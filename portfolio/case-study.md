# NovaCart - customer and revenue analytics case study

> **Portfolio note.** NovaCart is a fictional company. The dataset is synthetic and generated by
> this repository. This is a personal portfolio project, not client work, and no real business
> impact is claimed. Every number below is produced by the reproducible pipeline in this
> repository.

## Problem

A growing e-commerce retailer can see revenue rising but cannot answer the questions that decide
where money should go next: which categories and products carry the business, which customers
actually matter, whether newer cohorts retain, which marketing campaigns created value rather than
noise, and what to do about the products and segments that are slipping.

## Approach

Build the whole analytics path rather than a single analysis:

1. generate a realistic, seeded synthetic dataset with documented behaviour (15,000 customers,
   1,200 products, 84,263 orders over 24 months);
2. land it in PostgreSQL, enforce integrity in the schema, and treat the database as the source of
   truth for every metric definition;
3. build an analytical SQL layer (staging views, facts, marts) with raw-versus-analytics
   reconciliation;
4. build a Python analytics layer over those marts (KPIs, trends, products, customers, RFM,
   cohorts, campaign statistics) with unit tests on hand-built data;
5. export dashboard datasets, an executive summary and portfolio assets from the canonical
   results - never from hand-edited numbers;
6. run the whole thing through one fail-fast pipeline command.

## Architecture

```
synthetic generator -> CSV + manifest -> PostgreSQL raw layer -> analytical SQL
      -> Python analytics -> dashboard exports -> Power BI / executive summary / portfolio
```

![Architecture](screenshots/01_architecture.png)

Every layer downstream of the raw schema is derived and reconciled: 12 end-to-end metrics
(revenue, orders, units, customers, customer and product revenue totals, campaign assignments)
match across raw, analytical and exported layers with a zero difference.

## Analytical methods

| Area | Method |
| --- | --- |
| Revenue | Recognised net merchandise revenue: `items_subtotal - discount_amount` for completed orders; refunds, cancellations, shipping and VAT excluded. One definition, used by every layer |
| Trends | Daily, weekly and monthly series on complete calendars, with 7/30-day rolling windows and gap-safe month-over-month change |
| RFM | Quintile scores (ties broken deterministically by customer id) over recency, frequency and monetary value, assigned to business segments by documented priority rules |
| Cohorts | Monthly cohorts by first purchase month, retention by month offset with observability-aware blanks, month 0 = 100%, cumulative cohort revenue |
| Campaigns | Customer-level intention-to-treat comparison of the randomised treatment and holdout arms, on recognised revenue inside the campaign window |
| Statistics | Welch t-test, 95% Welch-Satterthwaite confidence interval, percentile bootstrap and Mann-Whitney robustness checks, Hedges' g effect size, Benjamini-Hochberg FDR control at 5% |
| Significance | Statistical (adjusted p < 0.05) and practical (>= 10% relative and >= EUR 5 absolute lift per assigned customer) reported separately |

## Key findings

| Finding | Value |
| --- | ---: |
| Recognised net revenue (24 months) | EUR 14,861,510 |
| Recognised orders / units | 78,896 / 250,532 |
| Purchasing customers (of 15,000 registered) | 7,622 |
| Average order value | EUR 188.37 |
| Repeat customer rate | 56.8% |
| Champions segment | 2,201 customers (14.7%) generating 84.7% of revenue |
| Revenue concentration | top 10% of buyers hold 53.0% of revenue; the bottom half hold 4.0% |
| Largest category | Electronics, 30.6% of revenue |
| Largest product | Marlow Smart Watch Pro, EUR 228,770 |
| Declining products | 162 of 1,118 comparable products (prior units >= 10 and unit change <= -30%) |
| Cohort retention | 24 cohorts; median month-1 activity retention 21.3% |
| Campaigns tested | 20; 8 statistically significant at FDR 5%, 11 clearing the practical thresholds |
| Largest campaign effect | CMP-005, +51.7% (EUR 110.86 per assigned customer, 95% CI EUR 75.16-146.55) |

Three campaigns were directionally positive but statistically inconclusive, and nine showed no
detectable difference - reported as such rather than being presented as wins.

## Limitations

* The data is synthetic. It demonstrates method and engineering, not a real commercial result.
* The dataset simulates randomised campaign assignment, while real client data often contains
  confounding, selection bias, targeting effects and non-random exposure.
* The primary campaign comparison is intention-to-treat and therefore diluted by treatment-arm
  members who were never exposed.
* The generator has no churn-decay process, so cohort retention is flatter than a real retail
  cohort, and the first cohort is left-censored (customers already active before the window) at
  73% month-1 retention versus ~21% for later cohorts.
* Revenue is heavy-tailed (the top decile holds 53% of revenue), so mean-based tests are
  complemented by bootstrap and rank-based checks but not replaced by them.
* Effect sizes for the significant campaigns are small (Hedges' g 0.11-0.24): large percentage
  lifts on small bases still produce modest standardised effects.

## Reproducing this case study

```bash
docker compose up -d
python scripts/run_pipeline.py          # generate -> load -> analyse -> export -> portfolio
python scripts/run_pipeline.py --list   # show the twelve steps
```

The pipeline stops at the first failure and prints the failing step, the reason and the completed
steps. See `docs/analytics_methods.md` for the full methodology and `powerbi/README.md` for the
dashboard build.
